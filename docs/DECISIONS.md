## D003 — 必要基础设施，不预建业务

## D007 — 当前修复记录
- TypeScript 7 的 CSS side-effect import 需要 Vite client 类型；添加 src/client/env.d.ts，类型检查复测通过。
- TypeScript 7 构建要求显式 rootDir；设为项目根，保留 server 输出的 src/server 路径。
- 浏览器测试发现 Phaser 的原 ESC 快捷键未触发暂停；改用有 repeat 防护的标准 DOM Escape 监听，实际按键冻结位置与动画验证。

- Vite 的 Phaser 单包约 1.44MB（gzip 约 380KB）触发 chunk 大小警告；Phase 0 保持简单，未隐藏警告，也不以拆包增加复杂度。

## D013 — Phase 2 性能采样

安装锁定依赖及 Playwright Chromium 后，从仓库根目录执行以下命令。原生 `before` 须取得 `baseline-canvas` 三个场景的实际样本，才进入优化步骤。复测沿用同一台机器、Chromium 版本、1280×960 视口和工作区文件系统。

```bash
node node_modules/typescript/bin/tsc -p scripts/performance/tsconfig.json
node --import tsx scripts/performance/run.ts before
node --import tsx scripts/performance/run.ts after --mock-ui scripts/performance/mock-ui.json
```

`before` 从 `62c5c2a10dff3afc18dbe875341f3a274ca3b436` 导出原样 Canvas 生产构建。另探测 Chromium 的 Canvas、WebGL 和 WebGL2 能力。Chromium 支持 Phaser 所用的 WebGL 上下文时，在独立副本只将 `Phaser.CANVAS` 改为 `Phaser.WEBGL`，结果归入 `baseline-webgl-variant`。保留 Chromium 沙箱，移除 Playwright 默认的 `--enable-unsafe-swiftshader`。报告记录实际游戏 canvas 上下文和 GPU 信息，headless 结果只适用于所报环境。

每个场景单独启动 Fastify，使用独立临时 SQLite。观察约 5 秒真实页面 RAF 及时间窗内的 20 Hz 回调，输出原始间隔和回调耗时、均值、最近秩 P95、平均 FPS 与实测回调频率。施工 fixture 预置已交材料和渡口位置，背包为空，使用普通按钮启动真实施工。该 fixture 仅用于性能负载。

基线对话为 `N/A`。接入 Mock 后，提供 `mock-ui.json`，其中 `input`、`send`、`pending`、`mockBadge` 填实际 UI 的 Playwright 选择器，`delayEnv` 填 Mock 延迟毫秒配置名，例如 `LLM_MOCK_DELAY_MS`。脚本用普通键盘接近岑砚，再经界面发送中文输入，验证采样首尾都显示等待。未提供配置时，`after` 仍可采三个共同场景，并将对话标为 `not-run`。子服务只收到白名单环境变量，关闭 Live 且没有 Key。

每次标准运行创建 `evidence/phase2/performance/<before|after>-<独立后缀>/`。`report.json` 包含环境、源码与锁文件哈希、能力探测、场景状态和样本。变体子目录存放 `build.log`、`<场景>.server.log`、`<场景>.browser.log` 和成功进入场景时的真实 `<场景>.png`。Chromium 启动失败写 `chromium.log`，保留已有证据，结束时清理临时副本、存档及子服务。

## D014 — 岑砚文字对话与独立预算

只在岑砚附近显式打开发送入口。服务端校验连接、交互距离、对话 ID、请求 ID 和世界代次。单个在途请求用异步 fetch 与 Abort 处理，完成时再核对归属。游戏存档事务和模型等待互相独立。成功往返仅在内存中保留至多八轮，并按 UTF-8 字节加消息开销估算和裁剪总上下文。岑砚的人格资料由 `data/npcs/cenyan.json` 独立管理。提示只取角色背景、公开桥况和玩家对白。输出作为安全文本展示。

同一存档旁的独立 SQLite 账本按模式分账，持久滑动窗口限制每分钟和每 60 分钟请求数，生命周期上限约束请求、Token 和 Live 金额。Live 配置要求明确单价、总金额上限及一个供应商支持的输出参数。调用前原子占用，收到可信用量再结算。缺用量、全零未确认用量、取消、失败或中断保留已占预算。总量超出输入与输出之和时，差额单独登记并按两者中的较高单价保守占用金额。推理等明细按供应商返回记录，属于已汇总的子集时不加总。对话故障单独显示并保留原玩法。真实供应商模式待另行验证。

## D017 — 岑砚实时对话关闭思考模式

硅基流动的 Qwen3.5 可以通过服务端配置 `LLM_ENABLE_THINKING=false` 关闭思考模式。留空时不发送该参数，以兼容其他供应商。硅基流动的 `max_tokens` 只限制可见输出，因此关闭思考可消除已观察到的额外推理开销。账本仍以供应商返回的输入和输出用量结算，输出总计已包含的推理 Token 不重复计费。游戏内金额是按配置单价计算的估算，取消或缺少用量时保留预留金额，实际收费由供应商结算。

## D019 — 共享请求和低频决策

`DialogueSession` 统一转发普通对白、玩家行动请求和自主计划，沿用 Phase 2 provider 与 thinking 三态。NPC 只有一个在途，旅人发送时可以取消在途自主并占一个等待槽。被取消调用结算后才让出槽位。新 World/会话/计划代次与交谈距离复核在提交之前完成。空白、格式错误或不可达等失败采用有限退避。待执行计划由 tick 推进。暂停或断线冻结世界，并且恢复后重新起算周期。

Live 对话由模型理解旅人意图，可直接返回对白，或以 JSON 返回非空对白与可选计划。只有通过 Zod 白名单的完整对象才能提出一至三步计划，所有可能携带计划的回复都复核计划代次。计划格式错误会短暂限制接受新计划，仍可交谈。有效对话期间只暂缓岑砚的执行，关闭或离开范围后继续已接受计划。模型内容与规则回执分开显示。账本升级时将 v1 请求保留为 dialogue，新增 autonomy 类型。自主和对话共同消耗总量，自主另有频率与总请求子预算，并为对话保留至少一个请求名额及总 Token、美元预算的 25%。模糊或未知用量和失败继续保留保守占用。Mock 自主和 Live 自主分别显式开启。

## D022 — 分批交材与共享施工（Phase 3.1）

交材在同一事务内提交材料扣减、工程缺口、具名贡献、规则记忆与唯一回执。指定物品与数量时，交付量取请求量、实际库存和工程缺口的最小值。省略物品与数量时分别交尽两种有效材料。无有效材料时保持世界状态。旅人成功交材的重试返回原回执。旧档已有材料及工时独立归入「旧档记录」。

施工统一在世界 tick 的动作判定之后推进。每个有效的未暂停 tick 汇总当前两人的有效施工，保持每人原来的 1 倍工速。最后一 tick 等分实际所需的剩余工时，工程进度、工时及实际重叠毫秒数同事务持久化。一方退出后另一方继续。完工记录随桥的通行更新一次，曾同时工作时写入合作事实。原 D011 的一次交齐门槛、D018 的施工互斥已被替换，对应既有测试改为核对实际入账、重复回执和共享工时，保留暂停、重启、原资源配方和单人全流程断言。

## D023 — 赠送、同行与计划策略（Phase 3.1）

- 木石赠送只允许旅人与岑砚。世界保留一个有效提议，期限 90 秒。旅人在对话面板发出正式提议，供应商需返回对应 ID 的接受或拒绝。岑砚用 `give_item` 提议，旅人用界面按钮给出决定。提出时不冻结材料。接受时检查发赠方、接收方、过期、距离、真实库存与容量后再事务转移。拒绝及失败无扣减。取消或无效的供应商答复作废本轮旅人提议。服务重启清理失去答复会话的旅人提议，岑砚已发出的有效提议仍可由旅人确认。
- 同行使用旅人的当前坐标。服务端按需重寻路，主动移动时按位置变化和 275ms 门限更新 A*，受阻时等候再试。保持约 22 像素停步间距和 8 像素碰撞边界。双方到旧桥范围且仍在交谈距离内就结束。连续不可达、60 秒活动时间、玩家结束同行或计划替换均能退出。同行结束和实际结果可进入长期记忆。
- `goal` 支持短自然语言，可带 `goal_tag`（`repair-bridge`、`stock-wood`、`rest`）。旧目标 ID 自动映射为对应标签。标签随待执行计划保存并在提升时生效，也用于选择相关记忆。继续或拒绝保留当前及待执行计划。替换先中断当前一步并清空原待执行计划，已提交材料与工时保留。暂缓在当前活动存在时占用唯一待执行位置。当前一步成功或失败结束时，以同一事务提升该计划，随后按正常规则重新校验。空闲时立即启动。第二个待执行提议返回拒绝。旧格式含计划的回复按 replace 处理，省略计划时按 reject 处理。
- 格式与提示共享 `capabilities` 的动作描述、目标、严格 JSON 示例、前置条件、执行和结果。计划允许 1–3 个严格步骤。对话或会话过期、连接接管和计划代次由服务端复核。仍有效的计划在关对话后继续。动作失败有类型、状态及实际变化，连续失败的自主请求退避。保存最新经过校验的结构化决策供 Debug 查看，包括有效赠送选择。提示取当前/待执行状态、近期结果与合作记忆，长文本只在上下文中缩短。
